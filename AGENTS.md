# AGENTS.md — AI agent context for this repository

Monorepo for **consumer hardware product development**, organized by engineering discipline. Every folder has a `purpose.txt` — read it before writing anything there.

## Repository map

- `products/<line>/` — product specs, requirements, variants, release records (points INTO discipline folders)
- `mechanical/` — CAD, enclosure, industrial design (CMF)
- `electronics/` — PCB/schematics, power, RF, devboards
- `firmware/` — bootloader, drivers, application, board support, on-device OTA agent
- `certification/` — regulatory evidence (India: BIS/WPC/TEC; export: FCC/CE; EMC; safety; environment)
- `manufacturing/` — DFM, assembly, test jigs, quality, yields
- `supply-chain/` — BOM, suppliers, costing
- `validation/` — reliability/thermal/battery/drop testing (hardware analog of software tests)
- `packaging/`, `test-tools/` — dielines/labels; jig software & calibration
- `business/`, `legal/`, `docs/` — human/agent documents; never mixed into engineering artifacts
- `sandbox/`, `labs/` — prototypes/research; never feed production directly
- `tooling/` — scripts + CAD/KiCad exporters (generated outputs are never hand-edited)

## Hard rules

1. Follow every `purpose.txt` — if a file does not belong per its folder's map, it does not belong there.
2. Artifacts live in discipline folders; `products/<line>/product.md` links to them — do not copy artifacts into product folders.
3. Generated files (STEP/STL/Gerber/PDF exports, cost rollups) are regenerated by `tooling/exporters/` — never edit them directly.
4. Never pre-create empty folders; scaffold only when the work arrives.
5. New folder ⇒ new `purpose.txt` (`PURPOSE:` / `SHOULD CONTAIN:` / `SEE:`).
6. Engineering decisions (platform choices, materials, CM selection) go through `rfcs/` first, then an ADR from `docs/decisions/TEMPLATE.md`.
7. Corporate docs (equity, HR, signed contracts, IP filings) never enter this repo.
8. Safety- or compliance-relevant claims require a linked source (standard number or lab report) in `certification/` or `validation/`.
